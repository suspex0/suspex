# CI

GitHub Actions (`.github/workflows/ci.yml`) runs on **`windows-latest`
only** — this is a Windows-only project; the C++ driver/agent side is not
built or tested in CI.

Two jobs, both from `orchestrator/` via `uv`:

| Job | Steps |
|---|---|
| `lint` | `uv sync --extra dev` → `uv run ruff check src tests` → `uv run mypy src/suspex` |
| `test` | `uv sync --extra dev` → `uv run pytest -q` |

## Lint/typecheck baselines

`ruff` (narrow select: `E4`, `E7`, `E9`, `F`, `I`) and `mypy`
(non-strict, `check_untyped_defs`) are configured in
`orchestrator/pyproject.toml`. The codebase predates both gates: the
pre-existing noise is pinned by documented `# legacy:` entries in
`[tool.ruff.lint.ignore]` / `[tool.ruff.lint.per-file-ignores]` and
`[[tool.mypy.overrides]]` blocks. The gate exists to catch **new**
undefined names, syntax errors, and type errors in checked modules — not
to reformat the codebase. `ruff format --check` is deliberately NOT run
(the tree is not format-clean; do not mix formatting churn with logic
changes).

New code gets no exemption: don't add entries to the legacy lists
without a `# legacy:` comment explaining them.

## Drift tests

Three test files pin documented surfaces to a committed snapshot
(`orchestrator/tests/tool_catalog.json`, regenerated by
`orchestrator/scripts/gen_tool_catalog.py`):

- `test_tool_catalog.py` — snapshot == live FastMCP registry (fails with
  "run `uv run python scripts/gen_tool_catalog.py`" on drift).
- `test_docs_drift.py` — `.kilo/skills/suspex0/SKILL.md` tool count and
  the `<!-- tool-table:start/end -->` region of `README.md` must match
  the catalog (real tools only; the deprecated `findings_manage` alias
  is not counted).
- `test_version.py` — `pyproject` `project.version`, `SERVER_VERSION`
  (date suffix ignored), and the latest `CHANGELOG.md` `## vX.Y` heading
  must agree.

When you add a tool or change a tool surface: update
`tests/_catalog.py` (`_TOOL_ACTIONS`, `TOOL_PURPOSE`), run
`uv run python scripts/gen_tool_catalog.py` from `orchestrator/`, and
commit the regenerated snapshot + README block.

`scripts/smoke_mcp.py` (repo root, needs a running server) loads its
expected tool set from the same catalog instead of a hardcoded list.
